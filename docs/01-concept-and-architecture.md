# Пункт 1. Концепция и архитектура ИСППР малого предприятия

## 1. Предметная область
Информационная система предназначена для руководителя малого предприятия и используется для управленческого финансового учета и анализа.

Функциональный фокус:
- учет выручки и затрат;
- анализ прибыли и рентабельности;
- контроль исполнения бюджета;
- анализ структуры затрат;
- оценка финансовой динамики;
- прогнозирование прибыли;
- формирование управленческих рекомендаций.

Система не является бухгалтерской программой и не заменяет регламентированный бухгалтерский учет.

## 2. Цели системы
- Обеспечить единый источник данных по операциям, бюджетам и аналитическим разрезам.
- Автоматически пересчитывать KPI и аналитику при изменении первичных данных.
- Выявлять риски по бюджету и прибыли до наступления критических отклонений.
- Поддерживать принятие управленческих решений через прогноз и рекомендации.

## 3. Архитектурная схема модулей
Целевая схема взаимодействия модулей:

`Database -> finance_engine -> ai_engine -> recommendation_engine -> Frontend`

Роли модулей:
- `Database`: хранение нормативно-справочной информации, операций, бюджетов и аудита.
- `finance_engine`: централизованные расчетные функции (прибыль, рентабельность, структура затрат, динамика, бюджет vs факт).
- `ai_engine`: прогноз прибыли на 1-3 месяца и оценка финансовой устойчивости.
- `recommendation_engine`: формирование рекомендаций на основе отклонений, трендов и прогнозных рисков.
- `Frontend`: ввод данных и визуализация KPI/аналитики/рекомендаций.

Принцип: бизнес-логика расчетов не размещается в контроллерах и UI, а выполняется только в прикладных движках.

## 4. Сущности базы данных
Обязательные сущности:
- `users`
- `pnl_items` (статьи P&L, тип: `income` / `expense`)
- `departments`
- `projects`
- `operations`
- `budgets`
- `audit_logs` (история действий)

### 4.1. Назначение сущностей
- `users`: пользователи системы.
- `pnl_items`: статьи доходов и расходов.
- `departments`: подразделения предприятия.
- `projects`: проекты предприятия.
- `operations`: финансовые операции (выручка/затраты).
- `budgets`: плановые суммы по статьям P&L в разрезе месяца.
- `audit_logs`: аудит действий (кто, когда, что изменил).

## 5. Связи (foreign keys)
- `pnl_items.user_id -> users.id`
- `departments.user_id -> users.id`
- `projects.user_id -> users.id`
- `operations.user_id -> users.id`
- `budgets.user_id -> users.id`
- `audit_logs.user_id -> users.id`

- `operations.(pnl_item_id, user_id) -> pnl_items.(id, user_id)`
- `operations.(department_id, user_id) -> departments.(id, user_id)`
- `operations.(project_id, user_id) -> projects.(id, user_id)` (опционально)
- `budgets.(pnl_item_id, user_id) -> pnl_items.(id, user_id)`

## 6. Ограничения целостности данных
- Операция всегда содержит:
  - дату (`operation_date`);
  - сумму (`amount > 0`);
  - статью P&L (`pnl_item_id`);
  - подразделение (`department_id`);
  - проект (`project_id`) допускается `NULL`.
- Статья P&L имеет тип только `income` или `expense`.
- Бюджет уникален в рамках пользователя, месяца и статьи:
  - `UNIQUE (user_id, period_month, pnl_item_id)`.
- Наименования справочников уникальны в пределах пользователя:
  - `UNIQUE (user_id, name)`.
- Все данные изолированы по пользователю через `user_id` и составные FK.
